# Free hosting: Render + MongoDB Atlas

Repository: https://github.com/AhmadI7san22/My-Projects
App directory: jo-hassa

The tracked render.yaml is a free Node web-service blueprint. When creating a Blueprint from the repository choose the file path jo-hassa/render.yaml. It uses rootDir jo-hassa, npm ci --include=dev && npm run build, npm start and /healthz. A manual Render Web Service can use the same settings with the Free instance type.

Use an Atlas Free cluster with a dedicated database named jo-hassa. Configure a least-privilege database user and allow the Render service outbound addresses in the Atlas network access list. Set MONGODB_URI only through Render's secret environment settings. Do not place connection strings or passwords in Git. SESSION_SECRET is generated by the blueprint.

Set BOOTSTRAP_ADMIN_EMAIL and a random BOOTSTRAP_ADMIN_PASSWORD of 16+ characters in Render. On an empty database startup creates the initial administrator, category metadata and site settings. It does not create fake news or reset existing accounts. Remove the bootstrap variables once the admin is created. Team accounts created locally are not automatically copied to Atlas; migrate them privately or create them in the hosted CMS.

RENDER_EXTERNAL_URL supplies the canonical origin automatically, unless PUBLIC_URL/CLIENT_ORIGIN are configured explicitly. The production server binds 0.0.0.0 and Render's PORT. HTTPS cookies remain enabled in production.

MEDIA_STORAGE=gridfs stores uploaded optimized WebP files and their responsive variants in MongoDB. This survives Render free-service restarts without needing a paid disk or separate image account. These images consume Atlas storage, so monitor the free cluster quota. CLOUDINARY_URL is also supported and takes precedence when configured.

Render free services sleep after 15 minutes of inactivity and can take about a minute to wake. Scheduled articles are published on the next scheduler scan after the service wakes; this tier cannot guarantee exact timed publication while asleep. This is a free-tier limitation, not a persistent background worker.

No account credentials, local database files, uploads, private exports or .env files belong in the published repository. Production deployment is complete only after the live URL, /healthz, editor login and persistent image uploads have been checked.

References: https://render.com/docs/free , https://render.com/docs/blueprint-spec , https://www.mongodb.com/docs/atlas/tutorial/deploy-free-tier-cluster/
